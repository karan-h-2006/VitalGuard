## Capture coverage notes & exceptions

1. **Upload controls**: The current VitalGuard web application has no file upload input in its user interface (all reports and data are generated system-side or streamed over MQTT/WebSockets). Consequently, no file upload state exists to capture.
2. **Device telemetry & abnormal simulator reading**: As demonstrated in screenshot `09_patient_dashboard_vitals_critical.png`, the platform captures the Critical acuity state (Heart Rate: 128 bpm, SpO2: 91%, Temp: 37.8°C, Acceleration: 0.4 m/s²) with the Critical Tier badge, status note explanation, and `Simulated device (demo)` indicator.
3. **Simulation scenario control**: As captured in screenshot `32_admin_patient_scenario_control.png`, administrators can dynamically control edge simulation scenarios (`Normal`, `Deteriorating`, `Noisy`) directly from the Patients governance tab.
4. **Physical hardware and SMS/email gateways**: Screenshots use synthetic request fixtures adhering to zero production credential disclosure. Hardware sensors and live SMS/email delivery gateways operate via sandboxed background workers and do not alter the user-facing web interface.
